# Change and Diff Analysis

## 1. Git-Based Diff Ingestion

ImpactMind processes code modifications from two primary input channels:
1. **Unified Diff Text**: Standard multi-file unified diff generated by tools such as `git diff HEAD~1` or local developer staging areas.
2. **GitHub Comparison Payload**: JSON response from the GitHub REST API (`/repos/{owner}/{repo}/compare/{base}...{head}`).

### Diff Parser Mechanics
The `GitDiffParser` decomposes raw diff streams into structured abstractions:
- **`FileDiff`**: Captures original path, target path, change status (`added`, `modified`, `deleted`, `renamed`), and hunk collections.
- **`DiffHunk`**: Parses unified diff hunk headers `@@ -old_start,old_count +new_start,new_count @@` to map line numbers directly to source AST intervals.

## 2. AST Change Classification Categories

ImpactMind classifies modifications into 13 mutually exclusive categories:

| Category | Description | Breaking Potential |
| :--- | :--- | :--- |
| `SIGNATURE_CHANGE` | Function/method parameter count, argument types, or return signature altered | **High** (if required parameters added or parameters deleted) |
| `PUBLIC_API_CHANGE` | Exported symbol, public class, or public interface modified or removed | **High** (if exported contract changed) |
| `LOGIC_CHANGE` | Internal function or method body implementation modified without signature changes | Low (backward-compatible internally) |
| `IMPORT_CHANGE` | Module import statements added, removed, or updated | Low to Medium |
| `CLASS_STRUCTURE_CHANGE` | Class attributes, member variables, or internal declarations altered | Medium |
| `INHERITANCE_CHANGE` | Base class inheritance or interface implementation contracts changed | **High** |
| `DATABASE_SCHEMA_CHANGE` | Alembic/Flyway/SQL migrations or ORM table column definitions modified | **High** (schema breaking risk) |
| `API_ROUTE_CHANGE` | HTTP endpoint decorators (`@router.get`, `@app.post`) or route handler parameters updated | **High** (external consumer break) |
| `DEPENDENCY_CHANGE` | Manifest files (`pyproject.toml`, `package.json`, `Cargo.toml`, `go.mod`) updated | Medium to High (dependency removal or version bump) |
| `TEST_CHANGE` | Test files, test cases, or testing fixtures modified | Low |
| `CONFIGURATION_CHANGE` | Environment, YAML, TOML, or JSON configuration files modified | Medium |
| `DOCUMENTATION_CHANGE` | Markdown, README, or documentation text modified | None |
| `UNKNOWN_CHANGE` | Unrecognized or binary file modifications | Low |

## 3. Breaking Change Detection Rules

A change is classified as `is_breaking = True` when any of the following heuristic criteria are met:
1. **Added Non-Optional Parameters**: New parameter without default value added to an existing function or method.
2. **Removed Parameters**: An existing parameter was deleted, causing callers providing that argument to fail.
3. **Public Symbol Deletion**: An exported class, interface, method, or function present in the previous snapshot was removed.
4. **Return Contract Alteration**: Annotated return type changed to an incompatible contract.
5. **Database Column Deletion / Alteration**: Table column removed or altered without backward-compatible default.
6. **Dependency Removal**: Existing direct package dependencies removed from manifest files.
